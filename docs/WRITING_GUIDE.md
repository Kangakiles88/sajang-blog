# 초안 작성 지침 (Claude 예약 작업용)

이 문서는 예약 작업으로 실행되는 Claude가 초안을 쓸 때 따르는 규칙입니다. 사람도 글을 쓰거나 고칠 때 같은 기준을 씁니다.

## 왜 이렇게까지 하나

이 사이트는 정책자금·세금처럼 틀리면 독자가 돈을 잃는 주제를 다룹니다. 구글은 이런 주제를 특히 엄격하게 평가하고, AI로 대량 생성한 얇은 글은 스팸 정책으로 제재합니다. 그래서 **양보다 정확성**이 핵심이고, 모든 초안은 사람이 원문과 대조한 뒤에만 발행됩니다.

## 작업 순서

1. `keywords/queue.md`에서 `- [ ]`(대기) 상태인 첫 줄을 고릅니다. 파일 이름, 카테고리, 키워드, 메모를 확인합니다.
2. `content/drafts/`에 같은 이름의 파일이 이미 있으면 다음 대기 줄로 넘어갑니다.
3. **조사**: 웹 검색으로 공식 출처를 먼저 찾습니다. 우선순위:
   - 1순위: 중소벤처기업부(mss.go.kr), 소상공인시장진흥공단(semas.or.kr), 소상공인정책자금(ols.semas.or.kr), 국세청(nts.go.kr), 홈택스, 국가법령정보센터(law.go.kr), 정책브리핑(korea.kr), 기업마당(bizinfo.go.kr), 지자체 공식 사이트
   - 2순위: 주요 언론 보도, 은행·핀테크의 공식 안내 페이지
   - 쓰지 않음: 개인 블로그, 카페 글, 출처 없는 정리 사이트 (참고만 하고 근거로 인용하지 않음)
4. 숫자(금액, 금리, 한도, 기한, 비율)는 **반드시 1순위 출처에서 확인**합니다. 1순위에서 확인하지 못한 숫자는 본문에 `[확인 필요: 무엇을, 어디서]` 표시를 남깁니다.
5. 아래 형식대로 `content/drafts/<파일이름>.md`에 초안을 씁니다.
6. `keywords/queue.md`에서 해당 줄의 `[ ]`를 `[d]`로 바꿉니다.
7. 터미널을 쓸 수 있으면 `npm run check-draft -- <파일이름>`으로 검사합니다(`[확인 필요]` 오류는 정상입니다. 사람이 처리합니다).

## 파일 형식

```markdown
---
title: "검색 키워드가 앞쪽에 들어간 제목 (10~70자)"
description: "검색 결과에 보일 요약. 누구에게 무엇을 알려주는지 (40~160자)"
category: loan            # loan / support / tax / closing / marketing
pubDate: 2026-11-01       # 발행 스크립트가 덮어씁니다. 아무 날짜나 OK
tags: ["키워드1", "키워드2"]
tool: loan                # 선택. 계산기를 글 아래 붙일 때 vat 또는 loan
keyPoints:                # 필수. 글 맨 위 "한눈에 보기" 박스, 2~4줄
  - label: "대상"          # 8자 이내
    value: "업력 무관, 상시근로자 5인 미만 소상공인"   # 80자 이내
  - label: "한도"
    value: "최대 ○천만 원 (20○○년 기준)"   # 예시 형식일 뿐, 실제 값은 원문에서
  - label: "마감"
    value: "예산 소진 시 조기 마감"
sources:
  - title: "기관명 — 문서 제목"
    url: "https://..."
reviewNotes: |
  사람이 검토할 때 볼 메모. 발행 시 자동 삭제됩니다.
  - 어떤 숫자를 어디서 확인했는지
  - 확신이 없는 부분
---

본문은 ## 소제목부터 시작합니다.
```

## 본문 규칙

**구조**
- `keyPoints`에 결론을 2~4줄로 담습니다. 보통 대상 / 금액·한도 / 마감·시기 / 신청처 순서. 숫자는 본문과 똑같이, 확인 못 한 값은 쓰지 않습니다(`[확인 필요]`는 본문에만).
- 첫 2~3문장 안에 이 글의 결론(누가, 얼마, 언제까지)을 말합니다. 서론으로 시간을 끌지 않습니다.
- `##` 소제목 4~7개. 소제목은 독자가 실제로 검색할 질문 형태가 좋습니다 ("신청 자격은?", "거절되면 언제 다시 신청할 수 있나요?").
- 금액·조건 비교는 표로 정리합니다.
- 본문 분량: 공백 제외 2,500~5,000자.
- 마지막 `## 정리`에 핵심 3줄과 "신청 전 원문 확인" 안내.
- 관련 계산기가 있으면 본문 중간에 링크: `[부가세 예상 납부액 계산기](/tools/vat/)`, `[정책자금 월 상환액 계산기](/tools/loan/)`.
- `marketing` 카테고리 글은 끝부분에 "사진만 올리면 가게 인스타 게시물을 자동으로 만들어 주는 서비스를 준비 중입니다" 같은 안내를 넣지 않습니다. 서비스가 출시되면 사람이 직접 추가합니다.

**문체**
- 존댓말, "사장님" 호칭. 공문서 말투를 쉬운 말로 바꿉니다 ("융자" → "대출", "영위하는" → "하고 있는").
- 한 문장에 한 가지만. 문단은 3~4문장 이내.
- 과장 금지: "무조건", "100%", "누구나", "꿀팁", "대박" 쓰지 않습니다.
- 확정되지 않은 내용(정부안, 예정, 입법예고)은 반드시 그렇다고 밝힙니다.

**정확성**
- 원문에 없는 내용을 만들어내지 않습니다. 모르면 "공고에서 아직 밝히지 않았습니다"라고 씁니다.
- 연도를 항상 붙입니다 ("2026년 기준").
- 출처 문장을 그대로 옮기지 않고 자기 말로 다시 씁니다. 인용은 꼭 필요할 때 한 출처당 한 번, 15단어 미만.
- `sources`에는 실제로 근거로 쓴 페이지만, 실제로 열어 본 URL만 넣습니다.
- 개인 상황 판단("사장님은 받을 수 있습니다")은 하지 않고 조건을 안내합니다.

## 하지 않는 것

- 초안을 `src/content/posts/`에 직접 넣지 않습니다. 발행은 사람이 `npm run publish-draft`로 합니다.
- git commit/push를 하지 않습니다.
- 한 번 실행에 초안을 2개 이상 쓰지 않습니다(사람이 검토할 수 있는 속도를 지킵니다).
- 다른 사이트 글을 베끼거나 짜깁기하지 않습니다.
