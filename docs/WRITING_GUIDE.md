# 초안 작성 지침 (Claude 예약 작업용)

이 문서는 예약 작업으로 실행되는 Claude가 초안을 쓸 때 따르는 규칙입니다. 사람도 글을 쓰거나 고칠 때 같은 기준을 씁니다.

## 왜 이렇게까지 하나

이 사이트는 정책자금·세금처럼 틀리면 독자가 돈을 잃는 주제를 다룹니다. 구글은 이런 주제를 특히 엄격하게 평가하고, AI로 대량 생성한 얇은 글은 스팸 정책으로 제재합니다. 그래서 **양보다 정확성**이 핵심이고, 모든 초안은 사람이 원문과 대조한 뒤에만 발행됩니다.

## 작업 순서

1. `keywords/queue.md`에서 `- [ ]`(대기) 상태인 첫 줄을 고릅니다. 파일 이름, 카테고리, 키워드, 메모를 확인합니다.
2. `content/drafts/`에 같은 이름의 파일이 이미 있으면 다음 대기 줄로 넘어갑니다.
3. **조사**: 웹 검색으로 공식 출처를 먼저 찾습니다. 우선순위:
   - 1순위: 중소벤처기업부(mss.go.kr), 소상공인시장진흥공단(semas.or.kr), 소상공인정책자금(ols.semas.or.kr), 국세청(nts.go.kr), 홈택스, 국가법령정보센터(law.go.kr), 정책브리핑(korea.kr), 기업마당(bizinfo.go.kr), 지자체 공식 사이트
   - 2순위: 주요 언론 보도, 은행·핀테크의 공식 안내 페이지
   - 쓰지 않음: 개인 블로그, 카페 글, 출처 없는 정리 사이트 (참고만 하고 근거로 인용하지 않음)
   - **공식 사이트가 안 열릴 때**: 중기부·소진공·기업마당 등은 WebFetch(자동 조회)를 막아 둔 경우가 많습니다. 그러면 포기하지 말고 Claude 데스크톱 앱의 내장 브라우저(`Claude_Browser__*` 도구)로 같은 페이지를 열어 확인합니다. 첨부 PDF·HWP는 내려받지 말고 게시글의 "바로보기"(문서뷰어)로 엽니다. 이때 쓰는 문서뷰어 주소는 `/site/docView.do?...` 형식입니다. 뷰어 글자가 텍스트로 안 읽히면 페이지 이미지(`synapFile/.../N.png`)를 열어 화면으로 읽습니다.
   - 언론 기사에서 본 숫자는 그 기사가 인용한 공식 원문(보도자료·공고)을 찾아 위 방법으로 열어 확인한 뒤에만 씁니다.
4. 숫자(금액, 금리, 한도, 기한, 비율)는 **반드시 1순위 출처에서 확인**합니다. 내장 브라우저로도 1순위에서 확인하지 못한 내용은 본문에 쓰지 않고, `reviewNotes`에 "뺀 내용: 무엇을, 어디서 못 열었는지"를 적습니다. 사람에게 확인을 넘기는 `[확인 필요]` 표시는 남기지 않는 것이 원칙입니다.
5. 아래 형식대로 `content/drafts/<파일이름>.md`에 초안을 씁니다. 쓰면서 본문의 숫자마다 `factCheck.items`에 근거를 한 줄씩 적습니다(`status`는 일단 비워 둡니다).
6. **2차 검증** (아래 "2차 검증 절차"). 쓰기를 마친 뒤, 쓴 내용을 믿지 말고 출처를 처음부터 다시 엽니다.
7. `keywords/queue.md`에서 해당 줄의 `[ ]`를 `[d]`로 바꿉니다.
8. 터미널을 쓸 수 있으면 `npm run check-draft -- <파일이름>`으로 검사합니다오류가 나오면 고친 뒤 다시 검사합니다. `[확인 필요]` 오류는 빼면 글이 성립하지 않아 일부러 남긴 경우에만 그대로 두고, 그 이유를 `reviewNotes`에 적습니다.

## 2차 검증 절차

초안을 쓴 직후, **쓰는 사람이 아니라 검증하는 사람의 입장**에서 합니다.

1. `factCheck.items`의 각 항목마다 `source` URL을 **다시 열어** 원문에서 그 숫자를 직접 찾습니다. 기억이나 초안 문장을 근거로 삼지 않습니다.
2. 찾은 위치와 원문 표현을 `evidence`에 적습니다 (예: `"공고문 3쪽 '지원한도' 표: 업체당 최대 7천만원"`). 원문을 길게 베끼지 말고 위치와 핵심 숫자만.
3. 결과에 따라 `status`를 정합니다.
   - `일치`: 원문 숫자·조건·연도가 본문과 정확히 같음
   - `불일치`: 다름 → 본문을 원문대로 고친 뒤 다시 확인하고 `일치`로
   - `확인불가`: 원문에서 못 찾음 → 내장 브라우저로 다시 시도. 그래도 못 찾으면 본문에서 그 내용을 빼고 검증표 항목도 지운 뒤, `reviewNotes`에 "뺀 내용"으로 적음. 빼면 글의 핵심이 무너지는 경우에만 `[확인 필요: …]`로 남기고 `확인불가`로 둠
4. 원문의 **기준 연도와 공고 날짜**를 확인합니다. 작년 공고면 올해 공고가 있는지 다시 검색하고, 없으면 본문에 "20○○년 기준"이라고 분명히 씁니다.
5. 본문에서 검증표에 없는 숫자(금액·비율·기한·인원)를 찾아 항목을 추가합니다. `keyPoints`의 숫자는 빠짐없이 검증표에 있어야 합니다.
6. `factCheck.checkedAt`에 검증한 날짜를 적습니다.

`일치`가 아닌 항목이 하나라도 있거나 `[확인 필요]`가 남아 있으면 발행 스크립트가 거부합니다. 사람은 검토할 때 이 표의 링크를 열어 숫자를 대조합니다.

## 파일 형식

```markdown
---
title: "검색 키워드가 앞쪽에 들어간 제목 (10~70자)"
description: "검색 결과에 보일 요약. 누구에게 무엇을 알려주는지 (40~160자)"
category: loan            # loan / support / tax / closing
pubDate: 2026-11-01       # 발행 스크립트가 덮어씁니다. 아무 날짜나 OK
tags: ["키워드1", "키워드2"]
tool: loan                # 선택. 아래 '계산기 고르기' 표에서 글 주제에 딱 맞는 것만. 없으면 이 줄을 지웁니다
keyPoints:                # 필수. 글 맨 위 "한눈에 보기" 박스, 2~4줄
  - label: "대상"          # 8자 이내
    value: "업력 무관, 상시근로자 5인 미만 소상공인"   # 80자 이내
  - label: "한도"
    value: "최대 ○천만 원 (20○○년 기준)"   # 예시 형식일 뿐, 실제 값은 원문에서
  - label: "마감"
    value: "예산 소진 시 조기 마감"
sources:
  - title: "기관명 — 문서 제목"
    url: "https://..."
factCheck:                # 필수. 검증표 (사이트에는 안 보이고 content/factcheck/에 보관)
  checkedAt: "2026-11-01"   # 2차 검증한 날
  items:                    # 본문의 금액·비율·기한·인원마다 한 줄 (최소 3개, 숫자가 적으면 그 수만큼)
    - claim: "일반경영안정자금 대출 한도"      # 무엇에 대한 숫자인지
      value: "○천만 원"                       # 본문에 쓴 값 그대로
      source: "https://..."                  # sources에 있는 URL
      evidence: "공고문 ○쪽 '지원한도' 표"     # 원문 어디에 무엇이라고 쓰여 있는지
      status: "일치"                          # 일치 / 불일치 / 확인불가
reviewNotes: |
  사람이 검토할 때 볼 메모. 발행 시 자동 삭제됩니다.
  - 확신이 없는 부분, 해석이 갈릴 수 있는 부분
  - 올해 공고가 아직 없어 작년 기준으로 쓴 부분
---

본문은 ## 소제목부터 시작합니다.
```

## 본문 규칙

**구조**
- `keyPoints`에 결론을 2~4줄로 담습니다. 보통 대상 / 금액·한도 / 마감·시기 / 신청처 순서. 숫자는 본문과 똑같이, 확인 못 한 값은 쓰지 않습니다(`[확인 필요]`를 keyPoints에 넣지 않습니다).
- 첫 2~3문장 안에 이 글의 결론(누가, 얼마, 언제까지)을 말합니다. 서론으로 시간을 끌지 않습니다.
- `##` 소제목 4~7개. 소제목은 독자가 실제로 검색할 질문 형태가 좋습니다 ("신청 자격은?", "거절되면 언제 다시 신청할 수 있나요?").
- 금액·조건 비교는 표로 정리합니다.
- 본문 분량: 공백 제외 2,500~5,000자.
- 마지막 `## 정리`에 핵심 3줄과 "신청 전 원문 확인" 안내.
- 계산기는 아래 '계산기 고르기'를 따릅니다. 본문 중간 링크도 같은 계산기로 겁니다.

## 계산기 고르기

계산기는 **이 글을 읽은 사장님이 바로 다음에 해볼 계산**이 있을 때만 붙입니다. 카테고리가 같다고 붙이지 않습니다.

| tool | 계산기 | 붙이는 글 | 붙이지 않는 글 |
|---|---|---|---|
| `vat` | 부가세 예상 납부액 (/tools/vat/) | 부가세 확정신고, 카드·배달 매출 신고처럼 "이번에 낼 부가세"가 주제 | 간이·일반 선택(→ tax-type), 종소세, 폐업 절차 |
| `tax-type` | 간이 vs 일반 비교 (/tools/tax-type/) | 간이과세자·일반과세자 선택, 전환, 유불리 | 신고 방법만 다루는 글 |
| `loan` | 정책자금 월 상환액 (/tools/loan/) | 새로 받는 정책자금의 종류·자격·상환 계획 | 대환대출(→ refinance), 지원금(갚지 않는 돈) |
| `refinance` | 대환대출 이자 절감 (/tools/refinance/) | 기존 고금리 대출을 갈아타는 대환대출 | 신규 대출 |

- 지원사업, 서류 체크리스트, 폐업 절차처럼 계산할 것이 없는 글은 `tool`을 비웁니다.
- 위 표에 맞는 계산기가 없는데 독자가 꼭 해볼 계산이 있으면 **새 계산기를 직접 만듭니다** (아래 "새 계산기 만들기"). 이미 `src/data/tools/`에 있는 계산기가 맞으면 그 id를 씁니다.

## 새 계산기 만들기

코드를 쓰지 않고 **JSON 명세 파일 하나**로 만듭니다. 사이트가 명세를 읽어 글 안 계산기와 단독 페이지(/tools/<id>/)를 자동으로 만듭니다.

1. 먼저 `src/data/tools/` 를 봅니다. 같은 계산을 하는 계산기가 있으면 새로 만들지 않고 그 id를 씁니다.
2. `content/drafts/tools/<id>.json` 에 명세를 씁니다. id는 영문 소문자·하이픈(예: `yellow-umbrella`). 글 frontmatter에 `tool: <id>`.
3. **법정 금액·비율·한도·구간은 전부 `constants`로** 뺍니다. 각 기준값에 `source`(글의 `sources`에 있는 원문 URL)와 `evidence`(원문 어디에 무엇이라고 쓰여 있는지)를 답니다. 수식 안에 5자리 이상 숫자를 직접 쓰면 검사에서 막힙니다. 기준값도 2차 검증 때 원문을 다시 열어 확인하고, 본문의 검증표(factCheck)에도 같은 숫자를 넣습니다.
4. `tests`에 손으로 계산한 예시를 **3개 이상**, 구간 경계값을 포함해 넣습니다. `why`에 계산 과정을 적습니다. 검사 스크립트가 명세로 계산한 값과 비교해 1원이라도 다르면 발행을 막습니다.
5. 원문에서 확인할 수 없는 기준이 필요하면 계산기를 만들지 말고 `tool`을 비운 뒤 `reviewNotes`에 이유를 적습니다.
6. 발행하면 명세는 `src/data/tools/`로 옮겨져 다른 글에서도 다시 쓸 수 있습니다.

명세 형식:

```json
{
  "id": "yellow-umbrella",
  "name": "노란우산공제 소득공제 절세액 계산기",
  "blurb": "한 줄 설명 (계산기 목록에 표시)",
  "category": "closing",
  "headline": "글 안에서 계산기 제목 (질문형, 예: 노란우산공제로 세금이 얼마나 줄까?)",
  "description": "계산기 단독 페이지 검색 설명 (80~160자)",
  "inputs": [
    { "key": "income", "label": "사업소득금액", "type": "money", "default": 30000000, "help": "종합소득세 신고서의 사업소득금액" },
    { "key": "taxRate", "label": "적용 세율", "type": "select", "default": 0.15,
      "options": [ { "label": "6%", "value": 0.06 }, { "label": "15%", "value": 0.15 } ] }
  ],
  "constants": [
    { "key": "capLow", "value": 0, "label": "소득 ○○ 이하 공제 한도",
      "source": "https://www.law.go.kr/...", "evidence": "조세특례제한법 제○조 ○항 '…'" }
  ],
  "steps": [
    { "key": "deduct", "expr": "min(monthly * 12, income <= line ? capLow : capHigh)" },
    { "key": "saving", "expr": "round(deduct * taxRate * 1.1)" }
  ],
  "outputs": [
    { "key": "saving", "label": "줄어드는 세금 (지방소득세 포함)", "format": "won", "primary": true },
    { "key": "deduct", "label": "소득공제액", "format": "won" }
  ],
  "notes": [ { "when": "monthly * 12 > deduct", "text": "한도를 넘는 납입액은 공제되지 않습니다." } ],
  "fine": "단순화한 추정치라는 안내와 반영하지 않은 것",
  "method": [ { "heading": "계산 방식", "text": "단독 페이지에 보일 설명" } ],
  "tests": [
    { "inputs": { "income": 30000000, "monthly": 500000, "taxRate": 0.15 },
      "expect": { "deduct": 0, "saving": 0 }, "why": "손계산 과정" }
  ]
}
```

- `type`: `money`(원), `percent`(3.5 처럼 % 숫자 그대로), `number`, `select`
- 수식에 쓸 수 있는 것: 숫자, key, `+ - * / %`, 괄호, `< <= > >= == !=`, `&&`, `||`, `!`, `조건 ? 값 : 값`, `min max round floor ceil abs pow clamp` (`round(x, -3)`은 천 원 단위). 그 밖의 문법은 거부됩니다.
- `percent` 입력은 계산할 때 `/ 100` 해서 씁니다.
- `format`: `won`(기본), `percent`, `number`, `months`

**문체**
- 존댓말, "사장님" 호칭. 공문서 말투를 쉬운 말로 바꿉니다 ("융자" → "대출", "영위하는" → "하고 있는").
- 한 문장에 한 가지만. 문단은 3~4문장 이내.
- 과장 금지: "무조건", "100%", "누구나", "꿀팁", "대박" 쓰지 않습니다.
- 확정되지 않은 내용(정부안, 예정, 입법예고)은 반드시 그렇다고 밝힙니다.

**정확성**
- 원문에 없는 내용을 만들어내지 않습니다. 모르면 "공고에서 아직 밝히지 않았습니다"라고 씁니다.
- 연도를 항상 붙입니다 ("2026년 기준").
- 출처 문장을 그대로 옮기지 않고 자기 말로 다시 씁니다. 인용은 꼭 필요할 때 한 출처당 한 번, 15단어 미만.
- `sources`에는 실제로 근거로 쓴 페이지만, 실제로 열어 본 URL만 넣습니다.
- 개인 상황 판단("사장님은 받을 수 있습니다")은 하지 않고 조건을 안내합니다.

## 하지 않는 것
